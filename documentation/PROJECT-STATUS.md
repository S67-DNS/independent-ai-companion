## 2. 明确不成立的「成果」

以下几条常被误读，这里直接写清：

- ❌ **「完整数字生命已实现」** — 不成立。身份、记忆、执行、通信的解耦仍在设计推进中，主体自主目标管理只到设想阶段。
- ❌ **「记忆召回已完整闭环」** — 不成立。召回文本进入模型请求体已有隔离证据，但证据由注入同一实现计算，缺请求体位置证明与关联 ID，且没有「不召回无关主体记忆」的反向用例。
- ❌ **「模型 / Runtime 可替换已验证」** — 不成立。集成中只有一个 Provider 和一个 Runtime，做的是「重启同一个」，不是「更换另一个」。
- ❌ **「端到端恰好一次投递」** — 不成立。「发送结果未知」必须保留不确定性，不得据此声称恰好一次。
- ❌ **「234/234 等于整体集成通过」** — 不成立。那是隔离施工期的历史回归记录，不等于本次集成通过。
- ❌ **「主动唤醒等于自主生活」** — 不成立。唤醒回合使用 Mock Runtime，主动出站保持关闭。
- ❌ **「正式环境已完整接入」** — 不成立。多项成果只在隔离工作树中成立，未部署到正式运行链路。

## 3. 证据强度分级

| 级别 | 含义 | 本资料中的例子 |
|---|---|---|
| 隔离环境真实执行 | 真实进程、真实 SQLite、真实请求体，但无真实渠道与外部模型 | 出站对抗用例、路径绕过对抗用例、完整请求体取证 |
| 隔离环境 Mock | 真实链路但模型/渠道由确定性替身承担 | 唤醒回合、SSE 完成标记、Provider 异常注入 |
| 静态检查 | 源码守卫、契约检查、配置比对 | 唯一写入入口扫描、契约 12/12 |
| 历史测试记录 | 过去某轮的回归结果，未在本轮重跑 | 234/234、各类 N/N 回归 |
| 只读生产观察 | 连续采样与前后快照，未改动任何数据 | 记忆连续性采样的部分结论 |
| 未执行 | 明确没有跑过 | 跨进程双写集成态重放、结果未知状态集成态重放、更换 Provider/Runtime |

**本资料不把多个局部 PASS 拼接成整体 PASS。** 隔离集成的独立复核结论是 `PASS WITH FIXES`，且明确限定于「已执行的隔离链路」，排除真实渠道与正式环境。

## 4. 工程经验与失败记录

真实失败方案与方法学修正单独成篇，见 `ENGINEERING-LESSONS/`：

- 子串匹配导致的路径绕过、相似目录误杀与目录联接绕过；
- 「静态读配置」不足以证明工具面被遮蔽，以及会话标题生成请求造成的取证误判；
- 测试脚手架误触被占用端口，以及随后引入的失败关闭护栏；
- Mock 与真实运行的边界被混淆时，如何重新界定验收口径。

## 5. 第三方成果的使用边界

开源零件（状态机持久化、轻量调度、事件溯源、来源追溯机制等）只作为**设计参考**归档与核验，未直接替代核心实现，也不为其成熟度背书。许可证核对见 `LICENSES/THIRD-PARTY-LICENSES.md`。
