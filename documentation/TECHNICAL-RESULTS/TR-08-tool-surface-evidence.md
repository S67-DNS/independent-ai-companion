# TR-08 工具面遮蔽验证与方法学修正

**状态**：已实现并验证（隔离环境）
**证据性质**：隔离实例跑真实回合 + **Mock 收到的完整请求体**落盘

## 1. 要解决的问题

「某个插件已经把记忆工具遮蔽掉了」这类结论，静态读配置是证明不了的：配置里写了禁用，不等于模型实际收到的工具面里没有。需要一个能反映**装配后真实请求**的取证方法。

## 2. 采用的技术方案

- 在隔离实例（独立端口、独立配置副本、Mock 模型、真实 MCP 行按对照需要禁用）中发起真实回合；
- 把 Mock 收到的**完整请求体**落盘，检查其中的 `tools` 数组与装配后的 `messages`；
- 以「`tools > 0` 且带唯一标记的 Agent 回合请求」为判据；
- 对遮蔽效果与未遮蔽项分别列出，不做「全部生效 / 全部失效」的笼统判断。

## 3. 方法学修正（本项最有价值的部分）

每个新会话会额外触发一次**会话标题生成**请求：它把用户原话嵌进 JSON 转发，且 `tools = 0`。若按「请求体包含标记」来匹配，会抓到这个标题生成请求，得出完全错误的工具面结论。修正后只取 `tools > 0` 且带标记的真实 Agent 回合请求。

这是一个可迁移的经验：**凡是以「模型实际收到什么」为判据的验证，必须先排除非业务请求，否则证据看起来完整但指向错误的样本。**

## 4. 可公开的验证证据

| 项目 | 结果 |
|---|---|
| 一组第三方记忆工具 | 在会话工具面中确实消失 |
| 对应提示段 | 确实被遮蔽 |
| 另一组全局记忆工具（含作用域设置） | **仍然出现在会话工具面** |
| 结论 | 遮蔽**只生效一半** |

配置组合校验：provider/model 为 Mock，目标 preset 均在，相关记忆与工具插件均已装载；隔离实例中真实渠道、外部服务等多个 MCP 行显式禁用，仅保留一个安全 MCP 作为正对照。

## 5. 当前限制

- 这是隔离实例 + Mock 模型的取证，**不是正式环境的运行时证明**。
- 结论是负面结论（遮蔽不完整），不是「已修复」；它揭示的是 L3 依赖插件遮蔽这一架构选择的结构性缺陷。
- 工具面清单随运行时版本变化，需要随版本升级重跑，不能一次性结论长期有效。
- 静态读 YAML / 配置推断工具面的做法被本项明确否证，不应再作为验收依据。

## 6. 尚未解决的问题

- 从「工具面遮蔽」升级为「可验证的记忆主体归属模型」。
- 工具注册与作用域覆盖语义在版本升级后的回归自动化。
- 自动注入安全与显式记忆工具检索安全的统一判定。
- 生产可观测性：缺少逐工具调用明细，导致部分验收只能判「部分通过」。
