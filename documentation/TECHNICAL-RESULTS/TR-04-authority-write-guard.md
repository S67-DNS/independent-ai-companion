# TR-04 权威路径写入守卫与路径绕过修复

**状态**：已实现并验证（隔离环境）
**证据性质**：隔离真实运行时对抗用例 + 单元矩阵 + 全量回归
**关联教训**：`ENGINEERING-LESSONS/EL-01-substring-path-bypass.md`

## 1. 要解决的问题

执行运行时的桌面端与工具链拥有文件写工具。权威记忆目录是控制面独占写入的资产，而运行时并没有「写入者租约」概念——工具可以在控制面不知情的情况下直接改文件。需要一个**前置**守卫，在工具执行前判定目标是否落在权威路径内并拒绝。

## 2. 采用的技术方案

- 在工具调用的前置守卫中读取**物化后的调用参数**（而非原始文本），文件类工具取 `file_path` / `path` 等键。
- 以会话工作目录为基准（与运行时自身的路径解析同源），对目标做**解析后比较**，而不是字符串包含判断。
- 处理相对路径、路径组合、相似目录名、目录联接（junction）与软链接越界。
- 拒绝时返回明确的守卫拒绝原因，且不产生新文件。

## 3. 实际完成的工作

- 用解析后比较替换旧版子串包含匹配；
- 补齐相对路径写、路径组合写、目录联接写三类对抗用例；
- 补齐相似名称目录的「正常写应放行」反向用例，避免误杀；
- 幂等挂载到运行时配置；
- 保留原有全部安全行为回归。

## 4. 可公开的验证证据

|---|---|---|
| 全量回归 | 234/234，0 skipped | 历史隔离施工期记录 |
| 单元矩阵 | 21/21 | 隔离环境实际执行 |
| 隔离真实运行时用例 | 7/7 | 隔离环境实际执行 |

## 5. 当前限制

- **234/234 是隔离施工期的历史测试记录，不等于整体集成通过**；该轮只修路径绕过，未改动写入所有权、来源追溯与投递队列。
- 守卫是**事前**拦截，只能覆盖经由该运行时工具链的写入；操作系统层面的直接文件修改仍可绕过。
- 因此来源信息必须与当前文件内容一致的运行时校验仍然必要，守卫不能替代它。
- 只读审查曾指出该类守卫在「会话启动事件」路径上可能因事件时序而失效，故该路径只作为纵深防御，不作为安全保证。

## 6. 尚未解决的问题

- 外部 Shell / 执行工具直接改文件绕过写侧来源校验的检测与自愈。
- 读取侧旧标签与当前文件内容不一致的风险。
- 守卫规则与运行时版本升级之间的兼容性回归。
- 自动注入安全与显式记忆工具检索安全是两件事，当前没有统一模型。

## 附：为什么这次失败值得公开

旧版实现用 `haystack.includes(root)` 判定。三个后果同时存在：相对路径 `../memory/x` 不含绝对拼写，直接绕过；名为 `memory-evil` 的普通目录被误杀；目录联接可绕过。**方向是 fail-open**，即「没匹配上就放行」——这是安全判定里最不该出现的默认行为。修正后改为按真实文件语义解析再比较，并把「相似目录应放行」写成反向用例，防止修复过头。
