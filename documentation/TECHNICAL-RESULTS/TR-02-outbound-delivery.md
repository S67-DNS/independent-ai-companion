# TR-02 出站统一调度、授权、幂等与回执（P1 / P2）

**状态**：已实现并验证（隔离环境）
**证据性质**：隔离环境实际执行 + Mock + 静态守卫检查
**明确边界**：未激活正式出站、未连接真实 `[COMMUNICATION_CHANNEL]`、未登录、未使用真实 `[MODEL_PROVIDER]`

## 1. 要解决的问题

多个模块各自发送消息会导致重复发送、乱序、状态不可判定。更危险的是：工具链可能绕过控制面直接调用发送接口，使权限策略形同虚设。此外，「请求已发出」与「渠道已收到」是两件不同的事，把二者混为一谈会造成盲目重发。

## 2. 采用的技术方案

- **唯一出站权威**：宿主控制出站，工具侧只提交发送意图，不直接发送。
- **单一 dispatcher**：所有派发集中在一处，配合两段式对账（发起 / 确认）与顺序约束。
- **进程级出站 Guard**：在业务模块求值前安装网络原语的预加载护栏，拦截指向正式端点的调用。
- **显式状态机**：已发送 / 待发送 / 发送中 / 发送结果未知，四态分离。
- **失败关闭**：测试模式与正式模式严格隔离；缺少测试模式标记时启动即抛错，绝不降级为正式直通。
- **配置校验**：必需的上游地址缺失、或非回路地址时，在模块导入阶段即拒绝启动。

## 3. 实际完成的工作

- P1：统一派发、两段式对账、出站 Guard、顺序约束、边界/依赖/正式分支用例、源码级守卫（除 dispatcher 外无直接派发调用）；
- P2：意图端点、拒绝与未实现响应、测试模式强制、配置注入、回复目标校验、审计记录；
- 对抗用例：把配置指向正式端口后调用只读能力，验证被拒绝、假正式端点计数为 0、审计含 blocked 原因。

## 5. 当前限制

- **全部证据来自隔离工作树 + 临时目录 + 本地 Mock + 非生产端口**，未向真实渠道成功发送任何消息。
- 上游入站权限判定与下游出站授权的**联合回归不完整**。
- 「发送结果未知」状态**不得自动重放**；本轮没有在集成态验证该状态的对账与恢复。
- **不能据此声称端到端恰好一次**：`已开始发送尝试` 不等于渠道已收到消息；未取得可靠渠道对账结果时不得盲目重发。
- 入站去重是进程内缓存，不是跨进程持久去重。

## 6. 尚未解决的问题

- 跨进程并发派发时的幂等保证（当前护栏是进程级）。
- 渠道侧可靠对账结果的获取与「结果未知 → 已确认」的状态迁移协议。
- 权限判定到记忆写入之间的端到端联合回归。
- 长期运行下租约过期接管与权威性混乱的检测。

## 附：一次公开可讲的失败

早期测试脚手架曾误触本机一个被占用的服务端口。这不是配置小疏忽，而是「测试环境默认可连真实端点」这一假设本身有问题。修正方式是引入回路地址校验、测试模式强制与业务模块求值前的网络原语预加载护栏，并把「假正式端点计数必须为 0」变成对抗用例。详见 `ENGINEERING-LESSONS/EL-03-test-harness-port-collision.md`。
