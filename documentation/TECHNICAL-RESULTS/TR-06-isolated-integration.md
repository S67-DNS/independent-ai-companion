# TR-06 隔离集成（Clean Room）全链路

**状态**：**已实现但验证不完整**
**证据性质**：隔离环境实际执行；独立复核结论 `PASS WITH FIXES`，**限定于已执行的隔离链路**
**明确排除**：真实 `[COMMUNICATION_CHANNEL]`、正式数据库、正式会话、外部 `[MODEL_PROVIDER]` 均未使用

## 1. 要解决的问题

各组件单独通过测试，不代表它们能一起运行。需要在一个与正式环境完全隔离的工作区里，把身份、权威记忆、记忆注入、执行运行时、模型请求、回合结束、网关权限、备份恢复串成一条链，并证明每一段确实发生了。

## 2. 采用的技术方案

- 独立运行时主目录、独立数据库、独立会话、独立写入状态、独立备份目录、独立端口；
- 确定性 Provider（不调用外部模型、不产生费用）；
- 模拟网关（合成事件，不连接真实渠道）；
- 全链路：入站 → 权限判定 → 主体初始化/恢复 → 记忆召回 → 注入实际模型上下文 → Session 创建/恢复 → Provider 生成 → 输出处理 → 合法记忆写入 → 持久化 → 备份恢复 → 出站；
- 受控停止与停止前后证据比对。

> 隔离工作区是**宿主机目录隔离**，不是操作系统级安全沙箱。

## 4. 当前限制（必须逐条保留）

1. **未使用真实通信渠道、正式数据库、正式会话或外部模型**；明确标注「正式环境未测试」。
2. **注入证据存在自证成分**：注入是否成立的标记由与注入同一实现计算的字符串包含判断得出；缺少 `messages[]` 中的角色 / 位置证明，缺少与注入清单哈希或代数的关联 ID。
3. **未构造「不召回无关主体记忆」的反向用例**；无法证明主体隔离。
4. **网关拒绝缺集成态反证**：集成层只跑了 1 条放行；四类拒绝只在单元测试中通过，没有「Provider 零请求 / 记忆零读写 / 无新 Session」的计数证据。
5. **跨进程双写与「发送结果未知」状态未在集成态重放**。
6. **全局只有一个 Provider 和一个 Runtime**：做的是「重启同一个」而非「更换另一个」，因此**模型可替换性与运行时可替换性均未被验证**。
7. 部分历史测试记录（如 234/234）未在本轮重跑，不等于本次集成通过。
8. 复核结论是 `PASS WITH FIXES` 而非 `PASS`；本资料不把多个局部通过拼接成整体通过。

## 5. 尚未解决的问题

- 上述 1–7 每一项都是待补证据，而不是待加功能；优先级高于新特性。
- 至少两个真实 Provider / 两个 Runtime 的交叉替换实验。
- 关联 ID 贯穿全链路，使每一阶段可核对到同一请求。
- 正式环境与隔离环境之间的配置漂移检测，以及回滚后的资产一致性断言。

## 6. 一句话结论

**隔离链路确实跑通了，且证据是可查的；但「已实现完整数字生命」「可替换性已验证」「记忆闭环已成立」三种说法，当前证据都不支持。**
