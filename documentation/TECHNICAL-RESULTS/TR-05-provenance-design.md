# TR-05 记忆来源追溯 / CAS 数据模型与契约

**状态**：**已完成设计，尚未实施**（端到端）
**证据性质**：只读盘点 + 设计文档；**不是**运行验证

## 1. 要解决的问题

并发写入、外部直接修改、内容漂移，会让「这条记忆是不是当前主体写的、是不是当前版本」无法判定。若来源、版本与内容校验混在一起，审计既不能定位责任，也不能阻止错误覆盖。

## 2. 采用的技术方案（设计）

- **职责分离**：权威记忆**正文不进关系型数据库**；数据库只保存注册表、预约、审计与元数据，正文以独立文件保存。
- **写入协议**：预约（reservation）→ 期望哈希（expected hash）→ 内容寻址（CAS）→ 代数（generation）递增 → 审计。
- **排他性**：未过期的开放预约具有排他性，后到者无法进入比较与交换阶段。
- **信任分级**：权威 / 受信 / 不受信；只有权威与受信内容允许注入模型上下文。
- **漂移处理**：内容漂移时拒绝写入并留下拒绝证据，而不是静默覆盖。
- **结论分级**：静态可验证（有代码行号或只读 schema 实证）与未知（代码与配置都无法确定）严格区分，不猜。

## 3. 实际完成的工作

- 目标端记忆数据模型、Provenance 契约、CAS 与注入规则的只读盘点；
- 漂移 / 回滚 / 读副作用 / 提交钩子的契约设计；
- 按类型的聚合统计（**只公布统计口径，不公布明细**）；
- 后续隔离实现中的部分落地：预约 + 期望哈希 + 代数递增 + 写入后读回一致，以及备份恢复后的内容比较。

## 4. 可公开的验证证据

- 只读盘点报告在**不改动运行中系统**的前提下完成：源码只读、数据库以只读模式打开、未复制、未执行写语句。
- 隔离集成中有一次写入证据：预约 + 期望哈希 + 代数递增 + 写入后读回一致。
- 隔离集成中有一次备份恢复证据：原始文件级副本恢复到新目录后，5 个文件的内容比较一致。

> 以上只能证明**局部写入路径与备份比较**工作，不足以证明整套来源追溯体系已落地。

## 5. 当前限制

- **设计与只读盘点为主，尚未完成端到端实施与集成态验证**；不得描述为「来源追溯已完整可用」。
- 外部 Shell / 执行工具直接修改文件可绕过写侧来源校验。
- 读取侧存在旧标签与当前文件内容不一致的风险。
- **CAS、来源分类、内容哈希验证是三个不同概念，不可混为一个**：内容哈希证明字节一致，来源分类证明谁写的，CAS 证明并发下没有基于旧版本覆盖。
- 自动注入安全与显式记忆工具检索安全是两件事，当前没有统一模型。
- 预约的排他性结论来自静态盘点，未在跨进程并发压力下实测。

## 6. 尚未解决的问题

- 跨进程并发写入的完整压力测试与代数正确性证明。
- 候选事实的自动抽取与准入策略。
- 审计记录的长期保留、压缩与不可抵赖性。
- 「已完成设计」到「已实现并验证」之间的验收判据定义。
