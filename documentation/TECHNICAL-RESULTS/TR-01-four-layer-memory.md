# TR-01 四层记忆架构与检索 / 撤回 / 交接卡

**状态**：已实现并验证（隔离环境，有明确限制）
**证据性质**：隔离环境实际执行 + 只读运行采样

## 1. 要解决的问题

短期上下文、会话状态、历史归档与跨会话长期事实混在同一存储里，会带来三类问题：会话之间串话、撤回消息仍被检索到、会话窗口重置后主体连续性中断。此外，不同层的信任级别不同，不能一视同仁地注入模型上下文。

## 2. 采用的技术方案

按生命周期与信任级别划分四层：

| 层 | 职责 | 生命周期 |
|---|---|---|
| L0 工作上下文 | 近期消息与未读 | 单回合/短期，条目上限 |
| L1 会话轻量记忆 | 话题命中、唤醒提示、轻量状态 | 按类别过期或封顶 |
| L2 检索归档 | 追加式历史日志、带邻接上下文的检索、撤回 tombstone | 保留期 + 单文件行数上限 |
| L3 宿主全局长期记忆 | 跨会话长期事实 | 长期 |

前三层按会话键隔离；第四层通过工具面遮蔽与写入守卫限制访问。检索命中项附前后邻接消息作为上下文，但邻接项不计入命中数，撤回内容同时排除于匹配与上下文之外。会话重置时生成确定性、有字数上限的交接摘要，注入新窗口首轮上下文。

## 3. 实际完成的工作

- 四层各自的实现与生命周期管理；
- 检索过滤、上下文窗口、撤回 tombstone、L1 撤回对账；
- 新窗口交接卡（确定性生成、字数边界、失败不消费、同会话不重复、重启持久化、配置开关）；
- 每日整理任务；
- 针对非法参数、跨会话与撤回上下文的反向用例。

## 4. 可公开的验证证据

| 项目 | 结果 | 性质 |
|---|---|---|
| 记忆 / 撤回回归 | 20/20 | 隔离环境实际执行 |
| 检索与生命周期 | 9/9 | 隔离环境实际执行 |
| 合成检索基线 Recall@5 | 6/6 | 隔离环境实际执行 |
| 新窗口交接卡专项 | 7/7 | 隔离环境实际执行 |
| 撤回 tombstone 子项 | 5/5 | 只读运行采样（秒级采样 + 精确检索对照） |
| 之后能找回经历 | PASS | 只读运行采样，检索命中历史条目 |

一次只读运行采样还验证了 L0 记录新经历、回合后 L3 按来源归属新增、以及经历可被找回；四层记忆核心随后冻结不再改动。

## 5. 当前限制

- **L3 隔离不是物理隔离**：依赖插件遮蔽，实测曾发现遮蔽只生效一半（见 TR-08），这是结构性缺陷而非配置疏漏。
- **「记忆工具是否工作」在某次运行环境验收中仅判为部分通过**：该环境不记录工具调用明细，无法逐个区分 12 个工具中实际调用了哪些；完整断言来自隔离环境，不来自该环境。
- 交接卡是有损压缩摘要，**不等于**完整长期记忆恢复。
- 上述 N/N 多为历史回归记录，未在后续每次集成中重跑；不等于整体集成通过。

## 6. 尚未解决的问题

- 多会话、多 Agent 环境下记忆的**主体归属**缺少形式化模型；按会话键隔离回答不了「这条记忆属于谁」。
- 摘要与权威长期记忆之间的一致性协议未定义。
- 交接卡在并发主体下的归属未验证。
- 生产可观测性不足：缺少逐工具调用明细，导致部分结论只能判「部分通过」。
