# 事故：测试脚手架误触被占用的服务端口

## 发生了什么

出站链路的早期测试脚手架，在一次验证中误触了本机一个**已被真实服务占用**的端口。它没有走隔离的假端点，而是碰到了真实监听。

这件事被如实记为事故，没有从验收报告里抹掉。

## 根因不是「端口写错了」

真正的错误假设是：**测试环境默认可以连接真实端点**。只要这个假设成立，任何一次配置疏漏、环境变量缺失或默认值回退，都可能把测试流量送到正式链路。改一个端口号解决不了这类问题。

## 修正（三层护栏）

1. **地址校验**：必需的上游地址缺失时，在模块导入阶段即拒绝启动；非回路地址一律拒绝。
2. **模式强制**：测试模式与正式模式严格分离；缺少测试模式标记时启动即抛错，**不降级为正式直通**（fail-closed）。
3. **求值前预加载**：在业务模块求值之前安装网络原语护栏，拦截指向正式端点的调用；同时放置「假正式端点」，用计数必须为 0 作为对抗判据。

## 验证

对抗用例：把配置指向正式端点后调用只读能力 → 被拒绝，假正式端点计数 0，审计记录含 blocked 原因。出站回归 117/117（P1）与 131/131（P2），契约 12/12。

## 可迁移的教训

- 测试隔离不能靠「大家都记得用测试端口」，必须靠**启动时强制 + 求值前拦截 + 对抗计数**。
- 「没配就走默认」在涉及外部副作用的代码里是危险默认值；缺配置应当直接失败。
- 事故要写进验收报告，而不是只修代码；否则下一个接手的人会重新踩一次。
- 这类修正的价值在于把「人不会犯错」的假设，换成「错了也出不去」的结构。
