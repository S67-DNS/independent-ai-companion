# 未来研究路线

> 本文只讨论技术问题。每条方向都明确区分「已实现的基础」与「仍需研究的部分」。
> 不以愿景冒充能力：标注为「待研究」的，就是当前没有实现或没有验证的。

## 方向一：独立于模型的长期身份连续性

- **问题**：更换 `[MODEL_PROVIDER]` 后，主体身份、人格原则与长期关系如何保持不变？「身份」应该以什么形式被持有、被校验、被迁移？
- **已实现的基础**：身份与人格原则由核心持有，Runtime 只接收文本执行；隔离集成中验证了身份文本能进入模型请求体；重启后能恢复主体状态。
- **仍需研究**：身份的形式化表示与版本化；跨 Provider 的一致性度量；身份被渠道用语或模型自述改写的检测与拒绝；只有一个 Provider 的现状下，可替换性**尚未被验证**。

## 方向二：多层记忆的主体隔离与可信注入

- **问题**：多会话、多 Agent 共享记忆层时，一条记忆属于谁、谁能写、谁能信？注入模型的内容如何证明来源、权威级别与主体归属？
- **已实现的基础**：L0–L2 按会话键隔离；检索带上下文窗口与撤回 tombstone；注入侧有信任级别过滤；隔离集成中记忆文本进入请求体。
- **仍需研究**：L3 从「插件遮蔽」升级为可验证的主体归属模型；注入证据摆脱自证（需要请求体中角色/位置证明与关联 ID）；构造「不召回无关主体记忆」的反向用例；跨主体记忆污染的检测方法。

## 方向三：自动记忆形成与来源追溯

- **问题**：什么该被记住、由谁决定、如何记录来源与版本、外部直接改文件如何被发现？
- **已实现的基础**：预约 + 期望哈希 + 内容寻址 + 代数的写入设计；只读盘点确认权威正文与数据库元数据的职责分离；审计记录的设计。
- **仍需研究**：候选事实的抽取与准入策略；来源信息必须与当前内容一致的运行时校验；Shell / 工具直接修改绕过写侧来源校验的检测；读取侧旧标签与当前内容不一致的风险；**CAS、来源分类、内容哈希验证三者不可混为一个概念**。

## 方向四：长期反思与状态更新

- **问题**：长期运行中，主体如何基于经历更新自身状态，而不漂移、不累积错误、不覆盖权威事实？
- **已实现的基础**：每日整理任务、新窗口交接卡、L1 撤回对账；交接卡的确定性与持久化已验证。
- **仍需研究**：反思的触发条件与可解释性；摘要与权威长期记忆的一致性协议；状态更新的冲突消解；「有损压缩的交接摘要」与「完整记忆恢复」的边界。

## 方向五：Agent 自主目标管理

- **问题**：从「定时被唤醒」到「有目标地行动」，中间缺什么？
- **已实现的基础**：待命 / 定时注册 / 到点唤醒 / 重启恰好一次 / 失败重试调度，在隔离环境用 Mock Runtime 跑通。
- **仍需研究**：目标的产生、优先级、暂停与放弃；目标与权限边界的绑定；行动结果如何回流为经历；**当前唤醒回合使用 Mock Runtime，不构成自主生活的验证**。

## 方向六：可替换模型与 Runtime 的统一接口

- **问题**：能不能做到换模型、换执行运行时、换渠道，身份与记忆都不丢？
- **已实现的基础**：Provider Adapter 与 Runtime Adapter 的抽象契约；确定性 Provider 用于隔离验证；网关权限与主体解耦。
- **仍需研究**：至少两个真实 Provider / 两个 Runtime 的交叉替换实验；接口差异的适配层成本；替换前后身份与记忆的一致性自动比对；**当前没有做过「更换」实验，只做过「重启同一个」**。

## 方向七：记忆、行动与经历之间的闭环

- **问题**：记忆如何影响行动，行动结果如何成为新的记忆，且链条可追溯、可重放、可回滚？
- **已实现的基础**：出站队列、回执与幂等状态机；唤醒链路中的记忆连续性检查；备份与隔离恢复比较。
- **仍需研究**：行动结果到记忆条目的自动准入；闭环的关联 ID 贯穿；「发送结果未知」状态在集成态的重放与对账；跨进程并发双写的集成态验证（当前未执行）。

## 方向八：长期运行中的安全、权限与可恢复性

- **问题**：默认拒绝能否覆盖所有入口？备份恢复能否证明一致性而不只是文件存在？
- **已实现的基础**：入站默认拒绝且拒绝早于模型/工具/唤醒/记忆；测试模式失败关闭；权威路径写入守卫；原始文件级备份与隔离恢复比较；受控停止无残留监听。
- **仍需研究**：权限判定与记忆写入之间的端到端联合回归；外部工具绕过守卫的持续检测；恢复后「可继续写入」的验证；长期运行下的租约过期、接管与权威性混乱；生产可观测性不足（缺少逐工具调用明细）。

## 优先级建议（供讨论，不是承诺）

1. **先补证据，不先加功能**：注入证据去自证、反向用例、跨进程双写与结果未知状态重放。
2. **再做可替换性实验**：两个 Provider / 两个 Runtime 的交叉验证，这是架构主张成立与否的关键判据。
3. **最后才谈自主性**：目标管理、反思与经历闭环目前是设想，不应在证据基础补齐前推进。

## 明确不列入路线的事

- 不把发表、产品化、成熟度包装作为目标。
- 不引入需要大型分布式系统才能解决的本地单机问题。
- 不为使用某个框架而增加依赖。
- 不使用任何私人经历、消息原文或人物设定作为研究案例。
