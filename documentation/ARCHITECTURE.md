# 抽象技术架构

> 本文只描述抽象分层与契约，不含任何具体部署路径、端口、账号、产品版本或运行实例信息。
> 所有名称均按 `README.md` 的占位符表抽象化。架构图用纯文本表示，不使用截图。

## 1. 分层

```
┌──────────────────────────────────────────────────────────────┐
│  [COMMUNICATION_CHANNEL] 适配器                               │
│  入站鉴权 · 默认拒绝 · 出站投递 · 回执与幂等                  │
└───────────────┬──────────────────────────────┬───────────────┘
                │ 已授权事件                    │ 出站结果
                ▼                              ▲
┌──────────────────────────────────────────────────────────────┐
│  [CORE_ENTITY] 核心（控制面）                                │
│  身份 · 人格原则 · 关系与长期连续性 · 记忆访问授权           │
│  Runtime 选择 · Provider 选择 · 渠道↔主体绑定                │
└───────┬──────────────────────────────┬──────────────┬────────┘
        │ 读取/注入                     │ 写入授权     │ 会话映射
        ▼                              ▼              ▼
┌───────────────────┐  ┌────────────────────────┐  ┌──────────────────┐
│ 权威记忆系统       │  │ 写入安全链             │  │ Agent Runtime     │
│ L0–L3 四层        │◄─┤ 写入闸门 → 写入所有权  │  │ Session 生命周期  │
│ 检索 · 注入 · CAS  │  │ → 预约/期望哈希 → 审计 │  │ 工具调用 · 事件   │
└───────────────────┘  └────────────────────────┘  └────────┬─────────┘
                                                              │ 模型请求
                                                              ▼
                                                ┌────────────────────────┐
                                                │ Provider Adapter       │
                                                │ [MODEL_PROVIDER] 可替换 │
                                                │ 流式响应 · 超时 · 中断  │
                                                └────────────────────────┘
```

**数据流**：入站消息 → 身份与权限判定（默认拒绝）→ 主体初始化或恢复 → 记忆召回 → 注入实际模型上下文 → Runtime 创建/恢复 Session → Provider 生成 → 输出处理 → 合法记忆写入 → 持久化与备份 → 出站投递。

**关键时序约束**：权限判定必须发生在模型调用、工具链、主体唤醒与记忆写入**之前**；写入必须在持有写入所有权的事务内完成，并在提交前复核所有权。

## 2. 四层记忆架构

| 层 | 职责 | 生命周期 | 隔离方式 |
|---|---|---|---|
| L0 工作上下文 | 近期消息、未读、当前回合 | 单回合/短期，有条目上限 | 按会话键 |
| L1 会话轻量记忆 | 话题命中、唤醒提示、轻量状态 | 按类别过期或封顶 | 按会话键 |
| L2 检索归档 | 追加式历史日志、上下文窗口检索、撤回 tombstone | 有保留期与单文件行数上限 | 按会话键 |
| L3 宿主全局长期记忆 | 跨会话长期事实 | 长期 | 依赖插件遮蔽与写入守卫，**非物理隔离** |

- **形成**：从回合结果抽取候选事实 → 写入授权 → 落入对应层。
- **检索**：按会话键过滤，命中项附前后邻接上下文，撤回内容不参与匹配。
- **注入**：只有权威级别或受信级别的内容可进入模型上下文；注入需保留来源、版本与权威级别，并证明它**确实进入请求体**。
- **更新**：预约 + 期望哈希 + 内容寻址 + 代数（generation）+ 审计；内容漂移时拒绝并标记，而不是静默覆盖。
- **已知结构性缺陷**：L3 的归属隔离依赖工具面遮蔽，实测曾出现「只遮蔽一半」；这属于架构层待解决问题，见 `RESEARCH-DIRECTIONS/RD-02-memory-subject-isolation.md`。

## 3. 身份与运行环境解耦

- **真相源**：身份与人格原则由核心自己持有，Runtime 只接收一段文本去执行；模型与渠道不得改写。
- **Session 映射**：渠道会话 → 主体 → Runtime Session 的绑定关系由核心持有，且绑定变更必须在持有写入所有权时完成；旧进程的延迟提交会因代数不匹配整体回滚。
- **连续性**：Session 结束不代表主体结束。新 Session 应恢复身份、相关记忆及其来源与版本；Runtime 重启不得丢失权威记忆。
- **可替换性边界**：Provider 与 Runtime 的接口是设计目标，但**当前集成只做过「重启同一个」，没有做过「更换另一个」**，因此不可声称已验证可替换性。

## 4. 写入安全与失败处理

| 机制 | 作用 | 明确不做的事 |
|---|---|---|
| 会话写入闸门 | 唯一受控写入入口，静态守卫确保无旁路写入 | 不替代跨进程所有权 |
| 写入所有权 / 栅栏 | 所有权、租约、代数落库；事务内 fresh read；提交前复核 | 不把进程内队列当跨进程锁 |
| 预约 + 期望哈希 | 未过期开放预约具排他性；内容变更时 CAS 拒绝 | 不把内容哈希校验等同于来源分类 |
| 审计 | 记录写入来源、版本、时间与结果，含拒绝证据 | 不记录可通过日志反推主体的正文 |
| 未完成写入队列 | 区分已确认持久、已接受、结果未知 | **结果未知不得自动重放** |

**权威级别判定**：只有确认持久（durable）才可报告写入完成；「已接受」与「结果未知」必须显式区分。

## 5. 出站、权限与幂等

- **权限**：入站默认拒绝；仅授权来源可放行；拒绝发生在任何模型、工具、唤醒与记忆操作之前。
- **出站**：宿主是唯一出站权威；工具侧只提交发送意图；单一 dispatcher 负责派发与对账。
- **幂等**：以运行标识与顺序约束避免重复发送；发送状态显式区分已发送、待发送、发送中、发送结果未知。
- **回执**：回执只提升到「渠道已确认」为止；「已开始发送尝试」**不**代表渠道收到消息。
- **失败关闭**：测试模式与正式模式严格分离，缺少测试模式标记时启动即失败，绝不降级为正式直通。

## 6. Provider 与 Runtime 适配

- Provider Adapter 统一流式响应、完成标记、正常结束、超时、异常与中断处理；确定性 Provider 用于隔离验证，不调用外部模型、不产生费用。
- Runtime Adapter 统一 Session 创建/恢复、提示接收、事件、分页读取、回合结束断言。
- 两者的共同约束：**替换不得改变身份与记忆**。这一约束目前是设计契约，缺少跨实现的实测证据。

## 7. 隔离、备份与恢复

- 隔离工作区使用独立运行时主目录、独立数据库、独立会话、独立写入状态、独立备份目录与独立端口；不与正式运行环境共享可写数据或配置。
- 备份为原始文件级副本，恢复在新目录中进行，并比较身份数据、记忆内容、内容寻址结果、来源信息、版本与权限状态；**只证明备份文件存在不算恢复通过**。
- 停止机制要求受控停止后无残留监听，并保留停止前后证据。
- 隔离工作区是**宿主机目录隔离**，不是操作系统级安全沙箱。
