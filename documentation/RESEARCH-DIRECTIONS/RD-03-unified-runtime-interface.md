# 未解决问题：可替换模型与 Runtime 的统一接口

## 问题陈述

「核心稳定、能力插件化、模型与平台可替换」是架构原则，但原则不是证据。真正的判据是：换掉 `[MODEL_PROVIDER]`、换掉 Agent Runtime、换掉 `[COMMUNICATION_CHANNEL]` 之后，身份、人格、记忆、权限边界与写入所有权是否**逐项保持不变**。

接口差异往往不在「调用哪个方法」，而在事件语义：回合结束的判据、分页序号的推导、工具注册的时机、流式完成标记、异常与中断的行为。

## 已实现的基础

- Provider Adapter 统一流式响应、完成标记、正常结束、超时、异常与中断；确定性 Provider 用于隔离验证；
- Runtime Adapter 统一会话创建/恢复、提示接收、事件、分页读取、回合结束断言（分页序号由会话投影动态推导，不硬编码）；
- 网关权限与主体解耦，拒绝发生在模型、工具、唤醒与记忆之前；
- 隔离集成完成过一次「停止并重启同一个」的连续性验证。

## 仍然缺失

- **全局只有一个 Provider 和一个 Runtime**；「更换」从未执行，只做过「重启同一个」；
- 没有替换前后身份与记忆一致性的自动比对；
- 没有接口差异的适配层成本评估；
- 网关四类拒绝只在单元测试通过，缺集成态「Provider 零请求 / 记忆零读写 / 无新 Session」的计数反证。

## 值得先做的实验

定义一份最小的「替换契约」：一组探针请求 + 一组必须保持不变的身份/记忆不变量 + 一份事件语义清单。引入第二个确定性 Provider 与第二个运行时实现，跑交叉矩阵；任何不变量漂移都记为契约缺口，而不是「适配一下就好」。

## 明确不主张

当前不主张「模型可替换」「运行时可替换」已被验证。这是本架构最需要被外部复核推翻或确认的一条假设。
