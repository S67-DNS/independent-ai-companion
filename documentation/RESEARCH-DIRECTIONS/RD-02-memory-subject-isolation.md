# 未解决问题：多层记忆的主体隔离与可信注入

## 问题陈述

按会话键隔离能防串话，但回答不了三个问题：一条记忆**属于谁**、**谁能写**、**谁能信**。当多个 Agent 共享一个全局记忆层时，读侧需要证明主体归属，写侧需要证明授权来源，注入侧需要证明内容带着正确的来源、版本与权威级别进入模型上下文。

## 已实现的基础

- L0–L2 按会话键隔离，L2 有保留期、行数上限、上下文窗口与撤回 tombstone；
- 注入侧按信任级别过滤（权威 / 受信可注入，不受信不可）；
- 隔离集成中记忆文本确实进入模型请求体；
- 写入侧有预约 + 期望哈希 + 内容寻址 + 审计的设计与局部实现。

## 仍然缺失（这一项的缺口最直接）

- **L3 依赖插件遮蔽，不是物理隔离**；实测曾发现遮蔽只生效一半，属结构性缺陷；
- **注入证据自证**：标记由与注入同一实现计算，缺 `messages[]` 中角色/位置证明与关联 ID；
- **没有反向用例**：未构造「不召回无关主体记忆」的场景，因此无法证明主体隔离；
- 来源信息必须与当前文件内容一致的运行时强制校验尚未实现。

## 值得先做的实验

1. 在注入清单与最终请求体之间建立可核对的关联 ID 与内容哈希链，消除自证。
2. 构造两个互不相关的主体与一组专属记忆，验证 A 的请求体中**从不出现** B 的记忆（反向用例优先于正向用例）。
3. 用外部工具直接改动一个记忆文件，验证读侧能发现来源与内容不一致并拒绝注入。

## 明确不主张

当前不主张「记忆闭环已成立」，也不主张「多主体记忆隔离已实现」。可以访问记忆、可以把文本送进请求体，与「可信地注入了属于正确主体的记忆」是三件事。
