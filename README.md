# Independent Companion

> **先读这一份 → [致后来接手这条路的人.txt](./致后来接手这条路的人.txt)**
>
> 为什么做这件事、哪些边界不能丢、接手时该守住什么。建议在读代码之前先看。

一套关于 **AI 身份连续性、长期记忆、写入安全、出站投递与本地交互** 的公开技术探索资料：自研源码、测试、本地窗口实现与工程文档。

**这不是产品发布，也不是可直接部署的完整 Agent。** 核心 sidecar 需要宿主 Agent Runtime 与消息网关；完整端到端链路未包含在本仓库、也未经验证。局部验证结果与已知失败用例均如实记录，不把 Mock 测试写成真实运行验证，不把局部链路写成完整闭环。

## 仓库内容

| 目录 | 内容 |
|---|---|
| `core/` | 核心 sidecar 源码：适配器、网关、宿主、生命周期、安全、数据模型与迁移 |
| `modules/state-core/` | 记忆与写入安全：来源追溯、CAS、写入栅栏、投递 outbox、权限守卫及对应测试 |
| `modules/bridge-utils/` | 通用桥接工具：健康/就绪、媒体规范化、敏感信息、锁、私有通道策略等 |
| `modules/ui/` | 本地窗口实现（可独立以 mock 通道运行）与控制台页面 |
| `documentation/` | 架构、技术成果、工程教训、研究方向、项目状态与第三方许可证核对结果 |
| `examples/` `tests/` | 通用示例配置与测试说明 |
| `致后来接手这条路的人.txt` | 项目起点与边界说明（公开版） |

## 快速验证（Node.js 22+）

```bash
node --test --test-concurrency=1 modules/state-core/tests/*.test.mjs
cd modules/ui/local-window && LOCAL_WINDOW_TRANSPORT=mock node server.mjs
```

集成测试还需要外部依赖 `js-yaml`（本仓库不附带）与 preset 资源目录；本仓库**不含**该资源目录，引用它的用例需自行准备资源。部分源码中的 `<WORKSPACE>/` 为脱敏路径占位常量，直接运行前需按本地目录结构调整——这是已知的、未修复的技术限制，未在此改写为「可运行」。

真实状态（既有隔离副本验证结果）：JS 语法检查 110/110；记忆/写入安全测试 92 例中 90 通过、2 失败（跨进程 SQLite 写锁相关，对照基线同样失败）；本地窗口 UI 页面、CSS、JS 与接口在 mock 通道下均返回 200。本仓库不含任何二进制、图片、字体、数据库或真实凭据。
